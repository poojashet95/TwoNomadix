# 11 — Rules and Project Memory

## Golden rules

1. Understand the existing code before changing it.
2. Keep frontend, backend and database responsibilities separate.
3. Use the existing service/repository architecture.
4. Do not put graph database queries in React.
5. Do not duplicate Axios calls throughout components.
6. Keep database credentials in backend environment variables.
7. Never commit `.env`.
8. Restart Vite after changing frontend environment variables.
9. Treat the seed script as destructive because it clears the graph.
10. Test API endpoints before debugging UI problems.
11. Check CORS when frontend and backend are on different origins.
12. Update image mappings when adding destinations.
13. Do not create separate React pages for every destination.
14. Preserve graph relationships because recommendations depend on them.
15. Test locally before deploying.
16. Check `git status` before committing.
17. Make small, meaningful commits.

## Interview explanation

> TwoNomadix is a graph-powered travel discovery and trip-planning application. The React frontend communicates with a FastAPI backend through REST APIs. The backend follows a route-service-repository architecture and uses a graph database to model relationships between destinations, attractions, categories, activities, hotels and restaurants. Recommendations are generated by traversing shared attraction categories in the graph. The frontend provides destination discovery, search, detailed destination information, recommendations and a client-side trip planner.

## Quick troubleshooting memory

If the UI says it cannot connect to the travel database:

```text
1. Start FastAPI
2. Open /health
3. Open /destinations
4. Check frontend/.env
5. Restart Vite
6. Check Network tab
7. Check CORS
```
